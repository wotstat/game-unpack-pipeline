# Дополнительный пул Selectel для pipeline: 25 октября 2026

Исследование официальных источников. Реальная ёмкость проекта и скорость workload
не измерялись; платные ресурсы не создавались. Предложения ниже сами по себе
не означают, что поддержка нового пула уже реализована.

## Кандидат

Рекомендуется добавить ручной резерв `ru-6c` в Москве, зона доступности 4.
`ru-6a`, `ru-6b` и `ru-6c` принадлежат одному мультизональному пулу `ru-6`.
[Локации Selectel](https://docs.selectel.ru/infrastructure/locations/).

Все три сегмента поддерживают HighFreq с выделенными ядрами и Ubuntu.
`ru-2c` и `ru-8a` поддерживают HighFreq без выделенных ядер, поэтому не дают
нужного отличия от существующего `ru-9a`.
[Доступность конфигураций и образов](https://docs.selectel.ru/cloud-servers/about/cloud-servers-availability-by-location/).

На момент проверки статус-панель показывает ограниченные ресурсы в `ru-6a`
и `ru-6b`, а `ru-6c` — работающим. Это аргумент в пользу первого теста в
`ru-6c`, но не гарантия размещения конкретной VM.
[Статус-панель](https://selectel.live/?lang=ru),
[FAQ о нехватке физических ресурсов при наличии квот](https://docs.selectel.ru/migrations/migrate-to-cloud-servers/faq-cloud-servers-migration/).

## Конфигурация и API

| Параметр | Значение |
| --- | --- |
| OpenStack region / пул | `ru-6` |
| Availability zone / сегмент | `ru-6c` |
| Предлагаемый фиксированный flavor | `HFL2.16-32768-256-INTEL`, ID `8111` |
| Ресурсы flavor | 16 vCPU, 32768 МБ RAM, 256 ГБ локального диска |
| Аналог AMD | `HFL2.16-32768-256-AMD`, ID `8062` |

Оба flavor относятся к HighFreq с выделенными ядрами. В `ru-6a`/`ru-6b`/`ru-6c`
перечислены Intel Xeon 6747P с частотой 3,8 ГГц и AMD EPYC 9474F с частотой
3,6 ГГц. HighFreq поддерживает локальный загрузочный диск и сеть до 3 Гбит/с.
Это не измерение скорости распаковки или загрузки данных.
[Конфигурации, процессоры и таблица flavor](https://docs.selectel.ru/cloud-servers/create/configurations/).

Выбор INTEL — инженерная рекомендация: сохраняется размер VM, но появляется
альтернативный класс физических хостов по сравнению с текущими AMD в `ru-3b`
и `ru-7`. Преимущество по времени выполнения пока не подтверждено бенчмарком.

Практическая проверка после исследования: [первый запуск в ru-6c](https://github.com/wotstat/game-unpack-pipeline/actions/runs/40156781780)
прошёл preflight, но Intel VM перешла в `ERROR` с `No valid host was found`.
Cleanup успешно удалил все ресурсы. Поэтому первоначальная рекомендация Intel
не подтверждена размещением; в workflow выбран AMD-аналог с теми же ресурсами.
Доступность AMD проверяется отдельным запуском, наличие flavor в каталоге её не гарантирует.

SMT включён по умолчанию. Его не нужно отключать, обязательное размещение
на одной NUMA-ноде также не требуется. Для создания VM CLI принимает имя
либо ID flavor и образа; образ должен находиться в том же пуле.
[Создание VM и дополнительные свойства](https://docs.selectel.ru/cloud-servers/create/create-server/).

Базовый Public Network API для прямого публичного IP:
`https://ru-6.cloud.api.selcloud.ru/public-network`.
Auth URL остаётся `https://cloud.api.selcloud.ru/identity/v3`.
[Официальный список API URL](https://docs.selectel.ru/api/urls/).

Для интеграции нужен отдельный выбор образа из `ru-6`: существующий UUID образа
`ru-7` нельзя переносить в другой пул. Можно сохранить действующий подход
pipeline: необязательная variable `SELECTEL_IMAGE_ID_RU_6`, иначе поиск
уникального `Ubuntu 24.04 LTS 64-bit` в выбранном регионе. Наличие именно
такого уникального имени должен проверить preflight; исследование его
не подтверждает авторизованным запросом к каталогу образов.

Добавление пула должно охватить основной workflow, checker, reconciler
и проверку отсутствия VM во всех поддерживаемых регионах перед удалением
общего emergency credential. Это вывод из текущих контрактов `AGENTS.md`
и lifecycle-кода репозитория.

## Что означает почасовая оплата

Selectel считает максимальное потребление квотируемых ресурсов проекта
в каждом астрономическом часе. vCPU, RAM, локальный диск и прямой публичный
IP относятся к таким ресурсам. Списание происходит раз в час за предыдущий
час; удалённые ресурсы перестают тарифицироваться со следующего часа.
[Модель оплаты](https://docs.selectel.ru/cloud-servers/about/payment/).

Следствие для одного изолированного run: выполнение за 50 минут с 10:05
до 10:55 может занять один оплачиваемый интервал, а те же 50 минут с 10:25
до 11:15 — два. Цель «быстрее часа» снижает риск дополнительного интервала,
но не гарантирует оплату только одного часа. Если в проекте параллельно
работают другие VM, счёт зависит от общего максимума ресурсов проекта
за каждый час, поэтому стоимость отдельных run нельзя просто суммировать.

Предпочтение более быстрого flavor имеет смысл подтвердить сравнением
полной длительности от создания ресурсов до cleanup и итогового потребления;
по одной частоте процессора гарантировать завершение pipeline за час нельзя.
